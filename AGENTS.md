# AGENTS.md

Versioniq is a Nextcloud app that lets administrators install an earlier or newer version of an app that is already installed: roll back after a broken update, or install a specific newer release to test compatibility. It is an admin-only utility with a PHP backend under `lib/` and a Vue frontend under `src/`, shown as a section in Settings, Administration (see `appinfo/info.xml`).

## Setup

Install the dependencies first:

```bash
composer install
npm ci
```

`package.json` asks for Node `^22.14 || ^24 || >=26` and npm `^11.3.0` (the CI workflows use Node 24).

To try the app, `docker-compose.yml` builds an evaluation image (Nextcloud with Versioniq and OpenRegister):

```bash
docker compose -f docker-compose.yml up -d --build
```

Then open http://localhost:8080/apps/versioniq/ and sign in as `admin` / `admin` (see `README.md`). `versioniq-compose.yaml` is a demo stack built from release tarballs; its header says it is not a development environment. For a disposable instance to run the end-to-end tests against, follow `docs/e2e.md`.

## Build

```bash
npm run build        # production frontend bundle (vite)
npm run dev          # development build
npm run watch        # development build, rebuilt on change
npm run l10n:build   # regenerate l10n/<locale>.js from l10n/<locale>.json
composer openapi     # regenerate openapi.json and check it with bin/openapi-design-rules.php
```

The documentation site in `docs/` is a separate Docusaurus project: `cd docs && npm run ci` installs its dependencies and builds it.

## Test

```bash
composer test:unit-only   # PHPUnit against mocked OCP interfaces (tests/phpunit-unit-only.xml), no Nextcloud needed
composer test:unit        # full PHPUnit suite (phpunit.xml); tests/bootstrap.php loads the Nextcloud server's tests/bootstrap.php, so the app must sit inside a server checkout
npm test                  # Vitest frontend tests
npm run test:e2e          # Playwright suite in tests/e2e/ against a running instance, see docs/e2e.md
```

`composer coverage:publish` measures PHP coverage and refreshes `coverage-summary.json` and the figure in `README.md`.

## Lint and quality

```bash
composer check:strict   # runs composer lint, cs:check and psalm, and reports all three
composer cs:fix         # apply php-cs-fixer fixes
npm run lint            # ESLint on src, tests and scripts, then scripts/check-l10n-keys.cjs
npm run stylelint       # Stylelint on src/**/*.{vue,scss,css}
npm run check:l10n-js   # fails when l10n/*.js is stale against l10n/*.json
```

The pull request lint check (`.github/workflows/pull-request-lint-check.yaml`) runs `npm ci` and `npm run lint`. The PHP quality suite runs in `.github/workflows/code-quality.yml`.

## OpenSpec flow

Feature work is specified in `openspec/` before it is built (`openspec/config.yaml` holds the project context and rules):

1. A change lives in `openspec/changes/<change-name>/` with `proposal.md`, `design.md`, `tasks.md`, `screens.md` and delta specs in `specs/<capability>/spec.md`.
2. When it is done, the change moves to `openspec/changes/archive/<YYYY-MM-DD>-<change-name>/` and its deltas are merged into the capability specs in `openspec/specs/<capability>/spec.md` (most capabilities also have a `screens.md`).
3. Code points back to the requirement it implements with an `@spec openspec/...` docblock tag.

`openspec/parity/` holds the competitor parity matrix that several proposals cite.

## Architecture decisions

Architecturally significant decisions are recorded as ADRs in `docs/adr/` (index in `docs/adr/README.md`). Per-change decisions live in the `## Decisions` sections of each change's `design.md`, under `openspec/changes/` and `openspec/changes/archive/`.

## Conventions

- Admin only. The UI is registered as an admin settings section in `appinfo/info.xml` (`lib/Settings/Admin.php`, `lib/Sections/AdminSection.php`), and controllers check the caller is an administrator (for example the `ChecksAdmin` trait in `lib/Controller/ChecksAdmin.php`).
- Backend code is grouped by what it does: `lib/Controller`, `lib/Service/<Area>` (for example `Source`, `Pin`, `Audit`, `Advisory`, `AutoUpdate`), `lib/BackgroundJob`, `lib/Command` (occ commands), `lib/Migration`.
- There is no page manifest; the frontend is a Vue app mounted from `src/main.ts` with `src/App.vue`.
- Translations: `l10n/<locale>.json` is the source; `l10n/<locale>.js` is generated by `npm run l10n:build`. User-visible strings in `src/` go through `t('versioniq', ...)` or `n('versioniq', ...)`, and `scripts/check-l10n-keys.cjs` checks every key is in `l10n/en.json` and `l10n/nl.json`.
- PHP, Vue and TypeScript source files carry an SPDX header (`SPDX-License-Identifier: EUPL-1.2`); `REUSE.toml` covers files that cannot carry one, such as the `l10n/` catalogues.
- Work branches come off `development`; see `CONTRIBUTING.md` for the branch and review rules.

## Commits

Conventional Commits (`CONTRIBUTING.md`, "Git Commit Messages"): `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, present tense and imperative mood, first line at most 72 characters.
